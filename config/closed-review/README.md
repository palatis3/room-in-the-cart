# Closed adult device review

Prepare an isolated deployment bundle from a reviewed commit. Copy the root package files, `api/`, `service/`, `shared/`, `.node-version` and `.vercelignore`, replace `api/index.js` with the entry in this directory, and install this directory’s Vercel configuration as the bundle’s `vercel.json`. The configuration builds only the service. Unmatched paths return 404 and the normal web assets are absent.

The dedicated entry requires `CLOSED_REVIEW_WINDOW_JSON` at runtime. Supply an object with ISO UTC `startsAt` and `endsAt`, one `householdId`, and exactly two existing adult Auth UUIDs in `subjects`. The lifetime is limited to 24 hours. Set `APPLE_ENVIRONMENT=Production` and set `APPLE_REVIEW_HOUSEHOLD_IDS` to the same single household UUID. Keep provider keys and automation credentials on the server. The native app continues to use its existing Supabase and service credentials.

Provision the fictional organizer and household privately first. The review surface admits the preconfigured household and two identities. It supports the second adult’s preview, explicit join and device enrollment, membership purchase context, verification, seat management and restore. Only the sandbox Apple notification endpoint accepts unauthenticated provider traffic. The existing worker endpoint retains its separate scheduler authentication.

Qualify the protected deployment and its rollback before exposing the signed hostname. Check the real provider population and public signup configuration, then confirm the two approved identities, the expected device paths, signed-out denials, filtered workspace results, Sandbox routing and the expiry boundary. At closure reapply host protection, restore the previous canonical binding and email-provider settings, revoke the fictional sessions and retain the exact rollback readback. Expiry immediately closes the review service. Supabase provider configuration and Vercel project settings have separate lifecycles.
