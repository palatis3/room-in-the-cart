# Standalone Form toggle control

This isolated app investigates the retained `f20feb6` sharing-flow switch failure. It is not a production target or a release gate. Lumpy prepared the original scaffold; the reviewed version uses dedicated target/bundle names, four fictional input/Done sequences, real mode/scope pickers and the same long switch label. The test retains pre/post screenshots, accessibility trees, state, geometry and timestamps. One trailing-coordinate tap must change value 0 to 1. Default XCTest idleness and 720/900-second allowances remain unchanged; there is no retry.

The app has no checkout model, storage, network, production styling or original navigation history. It is a comparison control, not a single-variable or identical-binary reproduction. Evidence capture can affect timing. A pass does not explain the original failure; a matching failure supports further framework/input investigation without proving the cause.

The workflow is opt-in: apply `diagnostic:form-toggle` once to the intended PR candidate, or dispatch the workflow with the exact SHA of its selected ref. A retained label does not trigger later pushes. The workflow checks out the immutable PR head, records both head and event/merge identities, and requires Xcode 27.1/27A9275, arm64 and iOS 27.0, recording the actual runtime build. A different environment fails the precondition instead of substituting a runtime. It creates a fresh iPhone 17 simulator, freezes source/products, executes once, verifies exact test execution and warning details, and retains six nonempty pre/post captures plus measured movement of the same switch around the drag. An ineffective drag is inconclusive. Missing evidence or a failed attempt cannot become a diagnostic pass.

Compare only with the instrumented real journey's separately identified products and results from the same hosted profile. Retained Xcode 26.3/iOS 26.2 results are a different environment and cannot be directly substituted for this migrated control. Keep the original failure and all required app checks unchanged. Local compilation/control runs with a different Xcode/runtime establish only that the diagnostic can execute locally.

The separately justified saved-checkout restoration fix changes the real app's pricing binding and adds independent cap scope. The control retains the original simplified Form structure. A later app pass therefore cannot isolate the original animation cause, even on the same hosted environment.
