# B03 shared placement reporting

Entry points: **Household → Shared placement reports** and **Shared household shop → Shared placement reports**. Shopper transfer remains the separate existing reviewed flow.

A current shopper explicitly reviews and saves the exact service shop snapshot while online. The protected record includes its original shop revision, authority epoch, source text/quote, actor/member/device binding, capture time, replay window and action identity. Saving the snapshot does not place an order or submit a report. After an external placement, the reporter enters the actual occurrence time, reviews it with that snapshot and approves. The exact report is sealed locally before delivery; the original snapshot, occurrence time, key and sending window never change on retry.

Opening saved original evidence is local-only and does not fetch the new shopper's basket. Same-process return from a retailer app can use a separate device-owner authentication step to unlock only the retained native actor's evidence while offline; this does not unlock current household data or restore shopper authority. After app restart, trusted account recovery is required before private captured records reopen. Stored JSON never chooses or authenticates an account.

The reporter command and minimal status lookup are scoped to the original shop independently of global current selection. The server still checks current authenticated membership/device, historical shopper authority and the original replay window for mutations. Minimal status lookup binds the exact original command digest and does not expose current revisions, budgets or another reporter's facts. An expired window is not renewed automatically. If its exact report has no recorded result, preserve the evidence for explicit follow-up with the current shopper. Only a never-sealed capture can be explicitly discarded and freshly reviewed; sealed reports cannot be rekeyed through that action.

The current assigned shopper explicitly refreshes the pending-report queue and reviews the immutable original snapshot/time alongside current shop/frozen identity. Apply requires the exact current frozen revision to match the reported snapshot. Reject preserves the report as rejected. Both actions persist exact command bytes before sending, retain stale/uncertain retries and use live current-shopper authorization. Status review can identify the original resolution action after a lost receipt; explicitly retiring a local reviewer retry does not undo a shared action.

The protected backup-excluded store uses actor-atomic updates, 0600 permissions and complete iOS file protection. Deletion epochs reject late writes. Global sign-out/account deletion purges it; household exit removes only that actor/household's records. Original actor-owned evidence and current-reviewer private data have distinct display boundaries. Losing only current-shopper authority clears reviewer data while preserving permitted original reporter evidence. True account/session loss clears all private projections.

These are manual reports about an external order. They do not charge a retailer, verify a retailer order or establish a payment status. No private local ledger content is automatically uploaded. See `service/API-PLACEMENT.md` for local service contracts and authorization details.
