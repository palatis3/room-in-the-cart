# N03 cook readback

The reusable API is `CookReadbackView(instruction: CookReadbackInstruction, authorize: (CookReadbackInstruction, Date) -> Bool)`. The projection contains a runtime-only `authorityBindingID`, `sourceID`, `sourceRevision`, `createdAt`, `startBefore`, exact `text`, `localeIdentifier`, and `excludesPrivateBudget`. It is intentionally not Codable. No persisted receipt, imported file, old note or paid seat supplies the authorization closure.

The Pickup parent must build the current reviewed, dated, budget-free cook projection and retain a current runtime binding. Its authorization closure must verify that the binding still belongs to the unlocked current workspace/persona, the source still exists, the source revision and exact content still match the reviewed projection, and any service authorization lease is current. A changed meal, usable fill, reservation, exclusion, instruction or scope must invalidate that projection. Bind the view to a fresh projection so `onChange` stops playback immediately; the model also checks the required closure every 250 ms while speaking/paused, and on every Play/Resume.

The agreed Pickup port creates an ephemeral instruction only from freshly prepared, budget-excluded text. It binds journey ID and current revision, preparation timestamp, locale, a runtime authority UUID, and current household/member/role scope. Authorization checks unlocked WorkspaceAccess, household lock state, permitted adult/local role, current shared identity expiry, the same journey/revision/exact text, and the budget exclusion flag. Edits, language, budget, source or scope changes invalidate the projection. Saving a note increments the journey revision and also invalidates playback until a fresh preparation. Archived notes never infer authority. An arbitrary editable draft or historical saved note must not be passed with an always-true closure.

The control displays the exact text, offers Read from beginning/Pause/Resume/Stop, and never starts automatically. It uses an installed local en-US/es-US synthesis voice and does not request microphone/speech-recognition permission. VoiceOver is exclusive: both the model and real audio adapter refuse Play/Resume when it is active; activation stops playback, and deactivation does not resume. Route disappearance, inactive/background transitions and audio interruptions stop playback. Returning to the route requires explicit Play and fresh authorization. There is no network fallback or food-text logging.

The Pickup binding permits starting or repeating playback for 60 seconds after preparation. This start deadline does not hide a still-current dated instruction or cut off the utterance that already started. Explicit Resume continues the same utterance only while the live authorization check still passes. Any actual authority or source change stops playback, including after the start deadline.

Eight deterministic tests cover exact text/locale, denied authority and private-budget refusal, VoiceOver exclusivity, changing source revisions, stale speech completion callbacks, authority checks on Resume, expiry during playback, route closure, and unavailable-voice typed fallback. The real AVSpeechSynthesizer adapter and SwiftUI control typecheck with the iOS 17 SDK. Physical-device voice availability, sound output, noisy-kitchen use, interruption and VoiceOver interaction remain unverified.

Files: `CookReadbackModel.swift`, `LocalCookSpeech.swift`, `CookReadbackView.swift`; tests: `ios/Tests/CookReadbackTests.swift`. The Capture catalog contains eight additional en/es strings. Pickup owns the concrete projection and authorization wiring. The isolated capture/readback suite passes 22 tests (14 capture, including actual Vision OCR, and 8 readback); this does not substitute for physical audio evidence.
