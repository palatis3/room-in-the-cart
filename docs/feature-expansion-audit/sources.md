### Feature 14 product identification

The batch editor can ask Open Food Facts for a product name and package wording after the shopper selects a GTIN. The v3.6 request asks for the product code, names, package quantity, and source update timestamp. The source link, retrieved date, and any accepted catalog wording accompany the shopper’s reviewed acquisition. The database uses ODbL and its individual contents use DbCL. The app reads the shopper’s selected photos on-device. [Product read contract](https://openfoodfacts.github.io/documentation/docs/Product-Opener/v3/products/get-api-v3-product-code/) · [Attribution and reuse terms](https://world.openfoodfacts.org/terms-of-use).

The publisher currently specifies 15 product reads per minute per IP, an identifying User-Agent, and a usage form before starting API use. The app limits reads to 12 per rolling minute, coalesces repeated queries, caches results within the current review session, and backs off on 429 or 503. Hosted fixtures use an injected transport. The release owner still needs to complete the publisher’s usage form and verify staging behavior before production activation. [Provider setup, limits and staging](https://openfoodfacts.github.io/documentation/docs/Product-Opener/api/).
