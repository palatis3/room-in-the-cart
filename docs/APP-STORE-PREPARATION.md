## Deferred Apple setup sequence

These steps are prepared for when the owner resumes paid Apple setup; this document does not request approval now or perform them.

1. **Account Holder:** confirm the correct paid Developer Program organization/team and legal seller. Accept the applicable current agreements personally; for paid features the Account Holder signs the Paid Apps Agreement. Complete Apple's applicable tax/banking requirements privately. [Agreements](https://developer.apple.com/help/app-store-connect/manage-agreements/sign-and-update-agreements/), [tax information](https://developer.apple.com/help/app-store-connect/manage-tax-information/provide-tax-information)
2. **App Manager/release owner:** register final bundle/extension identifiers and capabilities, then create the iOS app record with chosen name, primary language, matching bundle ID and owner-chosen SKU. Record the Apple-generated numeric App ID after creation. Apple's bundle ID must match the build; SKU cannot be changed after creation. [Create the record](https://developer.apple.com/help/app-store-connect/create-an-app-record/add-a-new-app/), [identity properties](https://developer.apple.com/help/app-store-connect/reference/app-information/app-information)
3. **Subscription owner:** create one Household subscription group and one annual auto-renewable product. Supply a permanent product ID, one-year duration, chosen US availability/price, approved group/product localizations, review screenshot and review notes. Keep Apple Family Sharing off for the specified two-named-adult seat model. Do not copy the development SKU or assume the research price. [Subscription setup](https://developer.apple.com/help/app-store-connect/manage-subscriptions/offer-auto-renewable-subscriptions/)
4. **Release/service owners:** set that exact product/bundle/environment in native production and server configuration; provision protected server credentials and separate sandbox/production notification destinations. Configure App Store Server NotificationsV2 and exercise Apple's test notification/status route. [Notification configuration](https://developer.apple.com/help/app-store-connect/configure-in-app-purchase-settings/enter-server-urls-for-app-store-server-notifications/), [V2 test guidance](https://developer.apple.com/documentation/AppStoreServerNotifications/enabling-app-store-server-notifications)
5. **QA/release owner:** fetch the actual product in a signed sandbox/TestFlight build; test localized offer, pending/cancel/unverified, durable delivery, renewal/grace/retry/expiry/refund, reinstall/second-device restore, wrong-household denial, two seats and Free retention. Local StoreKit fixtures and synthetic Apple SQL tests remain separate evidence.
6. **Operating owner:** finish production URLs, privacy/retention/support, measurement and guardian disclosures, hosted migrations/runtime/durable journal, real identity/SMTP/KWS and review accounts. Update only [production native configuration](../config/README.md); Release must never fall back to staging. Human US-Spanish and physical/mixed-phone gates remain before the full launch claim.
7. **Release owner:** capture final assets, complete the actual metadata/forms, upload the signed candidate, then add the first annual subscription **and its group with the new app version in the same review submission**. This last step remains unperformed and separately authorized. [First subscription submission](https://developer.apple.com/help/app-store-connect/manage-submissions-to-app-review/submit-an-in-app-purchase)
