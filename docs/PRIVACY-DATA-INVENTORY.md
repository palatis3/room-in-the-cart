# Privacy data inventory

Implementation inventory, updated 2026-11-20. Use this matrix to prepare the App Store privacy questionnaire. Reconcile the final signed build, enabled services and provider settings before publishing the answers. [Apple’s App Privacy definitions](https://developer.apple.com/app-store/app-privacy-details/)

The ordinary local Free workflow keeps its workspace on the iPhone. Signing into a household does not upload that existing workspace. Optional authenticated features transmit the specific account, household, request, shared-shop or billing data needed for those features. The manifest describes those optional collection paths even while email setup and real App Store product configuration remain deferred.

All listed data is treated as linked to identity and used for app functionality, and none is used for tracking. User ID, Other user content and Purchase history additionally support optional household outcome and retention analytics. These declarations do not authorize new uploads. Existing authorization and explicit review boundaries still control each transmission.

Household Tonight uses the requesting adult’s member ID to select their latest shared reaction to the same recipe revision from a shop where they were the shopper. For up to 90 days that reaction can break ties between dinner suggestions shown to that adult. Its influence fades with age. Withdrawing the reaction removes its influence. Record Product Personalization for linked User ID and Other User Content in the App Store privacy questionnaire when this service ships. Ordinary dictation and photo OCR run on the iPhone. An authorized adult can separately preview and submit one redacted text excerpt, selected image crop or temporary voice recording to OpenAI through the household service. Raw audio stays in memory through preview and submission and is cleared on successful transcription, dismissal, access loss or expiry. The provider’s own retention depends on its account and settings. Language assistance also requires an operator-priced allowance and an adult’s separate send decision. Depending on the purpose, the selected text travels with the offered public catalog entries, eligible private meal titles, IDs and reason codes, or reviewed match choices already visible to that adult. The operator can leave every provider purpose disabled. Contributor request submission sends the reviewed request to the household service. The spelling rule stays in the app’s protected local store. The app keeps local benchmarks and redacted diagnostic events on the device. Apple handles payment credentials and sends the app membership transaction evidence.

Confirming a receipt in the household pantry sends the merchant, purchase day and time zone, and selected lines to the household service. The adult must enter the printed transaction reference when photographing a household receipt in multiple sections. The reference is optional for other household receipt imports. Each line carries original wording, reviewed food, received and usable amounts, storage location and any entered paid total. Source identifiers, document line coordinates and a delivery link accompany the line when applicable. Adults with pantry access can read the receipt evidence. The original file is excluded from this request. Before submission, the app saves the reviewed command in protected, backup-excluded storage. An uncertain result offers the same command for a scoped retry. Clearing the retry removes the local copy and leaves any accepted household change in place. When an adult confirms a household receipt, the iPhone sends the selected lines’ wording and an opaque code used to prevent double counting. Typed and camera-reviewed receipts use the original wording of every draft row in order, including skipped rows. For imported files, the code covers every extracted page’s number and reading method, and each line’s position and original wording, before the shopper’s selection. For a receipt photographed in sections, the layout code also covers the photos in order. The iPhone sends a separate identifier derived from the first photo so the service can recognize the same source if the shopper later adds a section. The layout code is specific to the household and receipt. Skipped wording and the original photos or file stay on the device. Optional scan evidence: the camera/photo route requires per-review on-device-processing consent. It stores reduced JPEG references (location metadata stripped), original text, explicit product matches and literal receipt annotations only in protected, backup-excluded app-private storage. The bounds are twelve sidecars per namespace and 2.1 MB per encoded record. Individual reference removal, recipe-photo removal, pickup deletion, and whole-ledger deletion retire the corresponding evidence; foreground tombstone replay retries cleanup and prevents late recreation. Typed recipes retain original text in the recipe without a media sidecar. Photo bytes are included only when the person explicitly selects source references for an encrypted owner recovery file in Records, reviews their size and private-content disclosure, and supplies a user-held recovery key. Readable and helper exports omit attachment bytes. Sending a selected crop for online assistance is a separate action. Selected references are staged and validated with their records, then committed atomically as separate recovered evidence, without opening the original media namespace. Known source-reference removal markers scrub embedded evidence from earlier recovered copies while preserving their records and isolated workspaces, and prevent restoration through an older backup. Internal recovered media uses complete protection and is excluded from system backup. Apple may retrieve an explicitly selected iCloud photo before delivering it to the app. This adds local storage, not a new remote collection path.

New photos captured inside a recovered workspace belong to that independently opened physical SQLite workspace. A v1.2 owner attachment can describe the original capture UUID alongside its unchanged logical archive provenance; the imported description grants no file or cleanup access. A separate bounded, digest-checked local journal binds the recovery-copy ID, store kind and actual physical store ID. Cleanup verifies that journal against the actual SQLite store, retires that physical media/correction namespace, and then removes the isolated directory. Registry deletion cancels pending opens and waits for in-flight store users; stale rows cannot recreate the removed workspace. Removing only embedded source media retains the existing copy ID and its edited directory. Malformed journals and symbolic links fail closed; active root workspaces remain protected.

Shared placement evidence: explicit capture preserves the original authenticated shop snapshot, review time, authority epoch, actor/device binding and immutable report/reconciliation retry bytes in protected, backup-excluded local storage. Sending transmits the reviewed command's snapshot reference and occurrence time, not the private local ledger. Reporter status is minimal and remains distinct from current-shopper reconciliation data. Sign-out/account deletion and scoped household exit purge local evidence with a deletion epoch; a separately device-authenticated offline view can reopen only the retained native actor's original evidence, never current shopper authority. These reports are manually entered external-order evidence, not retailer or payment verification.

Optional pickup feedback starts off. Enabling it offers a prompt only on a closed, reported pickup. A saved response contains three codes for outcome, usual workflow and comparison with that workflow. It belongs to the pickup in the private local workspace and can travel in an explicitly exported owner recovery file. The app does not transmit it to an analytics service. Removing the response clears the current local record. Exported copies remain under their owner's control.

Separately consented household measurement transmits newly reviewed outcome, baseline and comparison response codes to the authenticated household service. It retains household/member/shop linkage, eligible week, consent identity and notice version, and consent/response timestamps. The service can match existing verified Production subscription state with current consent to assess household purchase retention. It does not import local feedback, grocery text, prices or member names into measurement. Withdrawal removes responses under that consent; account erasure removes associated measurement records. This linked collection is declared even though participation is optional. See `service/src/measurement.ts`, `service/migrations/019_optional_measurement.sql`, `ios/Features/Pickup/PickupFeedback.swift` and [the measurement contract](../service/API-MEASUREMENT.md). Copy, share-sheet completion and recipient acknowledgment are distinct actions.
