# Fresh next-shop closing choices stop linked meal carryover

The next-shop screen correctly omitted a handled/dismissed purchase, but its linked meal need could still appear in the new draft. `startNextShop` saved the newly chosen status in the next draft while filtering meal needs from only the previous draft's statuses. The filter now uses each validated current closing choice, falling back to the prior status, and still matches source line identity rather than food name.

The new native regression initially failed exactly at the meal-needs equality: all three same-named needs survived instead of just the still-open sibling. After the fix, all **9 FreeJourneyAcceptanceTests** passed, strict exit 0, with zero recorded runtime warnings or restarts. This includes the new handled/dismissed case, previous already-closed cases, persistence, replay, stale/concurrent reviews and the Free pickup lifecycle. The test verifies no new purchase, unchanged prior history and only one next draft after retry.

`before-*` and `after-*` preserve the source hashes, complete commands, native summaries and test exports. `strict.log` verifies the selected inventory and one start/pass per test. The temporary simulator shared with the earlier S02 acceptance was shut down and deleted after both tasks, with the preview untouched.

This changes newly created drafts. Already saved drafts and historical decisions are not silently rewritten. No confirmed stock is invented, and unrelated urgent needs remain open. The new regression directly exercises the persisted carried-meal branch; allocation-derived carryover uses the same corrected identity set, but no new dedicated allocation-branch scenario is claimed.
