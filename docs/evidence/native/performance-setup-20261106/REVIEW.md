# Independent performance setup review

No actionable finding in the reviewed patch. The new check requires a successful installed-app inventory and parse before declaring the Release bundle absent; the old check treated any get_app_container failure as absence. Source hashes and validation command are retained in `proof.json`.

- **Format compatibility:** `scripts/prepare_ios_performance_simulator.py:54–68` captures listapps output as bytes, passes it through the platform plist parser using stdin, then parses JSON. This supports the OpenStep plist representation without attempting to parse it as JSON directly. The converter's failure is fatal. The result must be a dictionary whose app entries are dictionaries; both the outer bundle key and each entry's CFBundleIdentifier are checked for the fixed Release bundle ID. Empty/malformed JSON, unexpected root type, and scalar entries cannot count as absence. A valid empty dictionary is accepted as an inventory without the app. Root reports a real local plutil check of representative OpenStep input; this independent review did not run native tools or verify a hosted inventory.
- **Fatal failure handling:** Every subprocess uses check=True. Boot, listapps, conversion/validation, and pasteboard/file-open failures propagate, mark the active receipt stage failed and prevent later setup actions. Main returns nonzero, including a conventional signal-derived subprocess exit status. Successful setup alone marks the overall receipt passed. The stage receipt is written via replacement before invoking its action, so a hard kill can leave a truthful running stage rather than a stale pass; the code does not claim a hard-killed action finished. Prior successful receipts are replaced at the next actual stage. Argument rejection occurs before any subprocess.
- **Behavior preservation:** The same boot helper is called; no installation, uninstall, erasure, retry, sleep, simulator change, or native-test change was added. The precise simulator UUID is validated; no booted alias is accepted. launch never opens or copies the fixture. rendered/scroll copy it exactly once only after verified absence. Commands use argument arrays rather than shell interpolation.
- **Privacy/evidence:** The installed-app inventory remains in process memory and piped parser input/output; it is not printed or written to setup.json. The receipt contains only fixed stage/case names, status, exit code and elapsed time. It is covered by the existing always-run performance evidence upload. Subprocess stderr remains ordinary failure diagnostics; no new raw inventory attachment or app-data read is introduced.
- **Gates and limits:** The only workflow hunk is the setup body at `.github/workflows/ios-performance.yml:140–145`. Setup stays 8 minutes, native step 30 minutes, job 40 minutes, XCTest allowances 900/1200 seconds. Matrix/selectors, one-test exact-execution checks, metric/sample/persistence requirements, baseline enforcement, warning policy, and original Release binaries remain unchanged. Setup failure still skips the native test; it is not converted to a warning or continue-on-error.

Validation performed: all 8 deterministic mocked-subprocess tests passed independently. They cover success ordering, each subprocess failure, wrong inventory shapes, app presence by both representations, missing fixture, invalid device alias, initial stage durability, and replacement of a prior successful receipt. These tests do not prove the next hosted listapps output or boot succeeds. No simulator, native executable, hosted action, Git mutation, shared-source edit, or subagent was used.
