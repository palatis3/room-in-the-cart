# Captured empty-price field measurement

Prepared before examining any completed S24DecisionPromptNov08 result. This is a read-only measurement tool, not a UI acceptance assertion. No canonical source or native execution is involved.

Run `python3 measure_field.py /absolute/path/to/field-crop.png --output /scratch/path/measurement.json`. The optional `--roi LEFT TOP RIGHT BOTTOM` uses original integer pixels with right/bottom exclusive. Prefer the explicit complete field crop and retain its accompanying frame TXT unchanged. Never resize the image before measuring.

The decoder checks original PNG chunk CRCs, records the source SHA256 and actual channel count, and supports noninterlaced 8-bit grayscale, RGB, indexed, grayscale-alpha and RGBA PNGs. It refuses nonopaque pixels because unknown alpha compositing would change the observed contrast. Other encodings fail explicitly. An explicit sRGB chunk with no ICC profile establishes the ratio's color-space assumption; otherwise the result remains conditional and needs profile-aware inspection.

The dominant exact RGB is the candidate background. Foreground pixels differ from it by at least 8 in one RGB channel. Eight-connected components touching crop edges, tiny marks, narrow caret-like components and long horizontal border-like components are excluded. This also excludes some legitimate narrow letters; it is deliberately not OCR. All excluded boxes remain in the JSON for review. The most frequent exact foreground RGB across the remaining components is the core candidate. A candidate requires at least eight retained components, the same candidate as a component's most frequent color in at least five components, and at least 50% background coverage before receiving a supported numerical assessment. These thresholds cannot establish the identity of text by themselves.

Report the candidate RGB, its pixel count, component support, dominant background RGB and contrast. Use standard sRGB linearization and relative luminance `0.2126 R + 0.7152 G + 0.0722 B`; contrast is `(lighter + 0.05)/(darker + 0.05)`. The 4.5:1 target applies to the normal-sized prompt. The darkest pixel is never a passing criterion, because a caret or edge may be darker than the intended prompt. Neither a single pixel nor one dark component can supply the required repeated support.

Before interpreting the ratio, visually confirm that this is the intended empty price prompt and that the retained component boxes track its glyphs. Inspect the top candidate histogram: antialias edges trend toward background, so a modal-color failure should be corroborated by a repeated glyph-core color rather than attributed to the darkest isolated pixel. A numerical result at or above 4.5:1 is still only a candidate pending this identity/core review. If the crop includes other labels, entered text, mixed backgrounds, connected borders, or insufficient component support, report inconclusive and use a documented tighter ROI inside the original crop. Do not add threshold retries to turn an inconclusive image into a pass.

`check_method.py` creates only temporary synthetic PNGs to check all supported channel encodings, light and dark backgrounds, rejection of alpha, and resistance to a black caret/border beside faint glyph-like shapes. Synthetic checks establish decoder/measurement behavior, not product accessibility. Completed light/dark captured images and physical/accessibility settings remain separate evidence.
