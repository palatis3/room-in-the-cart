## Why the public wrapper is insufficient

The patch replaces an actual built-in `XCTOSSignpostMetric` in the metrics array with an `NSObject` implementing `XCTMetric`. It forwards copying and the three public lifecycle/report methods, and leaves other metrics untouched. That preserves those public calls but changes runtime class identity, metric discovery/configuration opportunities, and optional-method presence. Apple's public contract describes custom metrics and per-iteration copies; it does **not** guarantee transparent decoration of a built-in collector. [Apple XCTMetric](https://developer.apple.com/documentation/xctest/xctmetric).

The observed null dates are consistent with some required built-in setup or lifecycle state failing to reach the delegate. **Class-specific framework setup is a plausible explanation, not a demonstrated cause.** There is no callback attachment or full assertion stack identifying which missing setup produced those dates. Supplying made-up bounds, spoofing the class, forwarding undocumented selectors, or swallowing the assertion would make the probe less trustworthy. Moving/duplicating `stopMeasuring()` would alter the original measurement without addressing the first observed error.
