# GitHub Actions Xcode availability and qualification

November 7, 2026, New York time

GitHub’s generally available `xcode-27` runner includes the same Xcode 27.1 build used in the local comparisons. Its standard simulator inventory differs from the local iOS 26.2 setup. GitHub’s traced Swift CodeQL support ends at macOS 26 and Xcode 26, so an Xcode 27 test qualification needs a separate Swift scanning lane. Apple lists macOS Sequoia 15.6 as the minimum for Xcode 26.3, macOS Tahoe 26.2 for Xcode 26.6, and macOS Tahoe 26.6 for Xcode 27.1 and 27.2. The app’s deployment target is iOS 17.0. All three Xcode generations accept that deployment target. Apple lists iOS 17 and later for Xcode 27 simulator and device support, and iOS 15 and later for Xcode 26.3 and 26.6. Minimum-OS testing still requires an installed iOS 17 runtime and a compatible device. Apple documents explicit runtime download and import. The listed Xcode 27 hosted image would require provisioning and checking iOS 26.2 (23C54) to match the local Xcode 27.1 runtime combination. The workstation reports macOS 27.2 (26B123), a separate host difference from the published runner. GitHub supports Swift through 6.3 in current CodeQL. Its tracing advisory calls for macOS 26 or earlier and Xcode 26 or earlier. The existing Swift scan uses manual Release build tracing, so its compatibility constraint applies separately from the simulator jobs. ## Qualification evidence

The prior macOS 26 arm64 qualification used Xcode 26.4.1 (17E202) and iOS 26.4 (23E254a). Its five ordinary UI cases and four Spanish cases passed with zero runtime warnings. The ordinary UI log still had a 60.04-second animation notification wait. The scroll case passed its assertions, but its original result database held only the three memory series. The missing required XCTest scroll-duration series failed qualification. The later f90 pinned environment emitted all five duration samples and passed all three Release performance gates. [Prior qualification audit](../toolchain-qualification-20261106/FINAL-AUDIT.json) · [f90 performance proof](performance/proof.json)

The current simulator chooser prefers the highest available runtime, then prefers an iPhone 17 within that runtime. A runner change therefore changes the selected OS unless the invocation pins it. The Release verifier matches the simulator, OS build, architecture, Xcode build, and test configuration against the approved performance profile. The existing profile covers Xcode 26.3 on iOS 26.2 (23C54). A new environment needs its own timing evidence before any baseline decision. [Current simulator chooser](../../../../scripts/select_ci_iphone.py) · [Approved performance profile](../../../../scripts/ios_performance_baselines.json)

A controlled Xcode 26 comparison can use the same `macos-26` image and explicitly selected iPhone 17 on iOS 26.2 with Xcode 26.3 and 26.6. An Xcode 27.1 comparison can hold that simulator runtime fixed only after verifying the provisioned runtime and exact build. For either comparison, use identical source, ordered selectors, time allowances, warning checks, and required scroll samples. Include a traced Swift scan on its supported Xcode 26 environment. The prior qualification and f90 observations set the criteria for another diagnostic comparison.
