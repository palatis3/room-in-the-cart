# Off-main speech-control assessment (proposal only)

The evidence supports investigating removal of the synchronous Pause wait from the UI actor. It does **not** establish a production correction or a way to clear the strict runtime-warning gate. The same six-frame Pause signature occurs in the retained serial-worker control, along with the other framework faults.

The retained worker source (`prior-worker-control.swift`) confines a lazily created synthesizer and all four commands to one default-QoS serial queue. Its SHA matches the earlier verification. It does not test delegates, audio-session ownership, authorization revocation, source changes, expiry, VoiceOver, cancellation, rapid reordering, or asynchronous acknowledgement. It is evidence that this minimal configuration ran and still warned, not an API guarantee or product qualification.

Apple documentation inspected does not mandate main-only calls or promise thread safety. The SDK marks the synthesizer non-Sendable. Therefore dispatching only pause/resume/stop while creation, speak, IDs and callbacks remain MainActor-owned would introduce cross-owner access without a supporting contract. Lowering QoS merely to hide the diagnostic is not a remedy. The existing app already performs blocking audio-session activation/deactivation on its dedicated queue.

A possible future experiment would require **one owner for the entire synthesizer lifecycle**, created/accessed/destroyed there; immutable commands tagged with playback generation; explicit result acknowledgements; and callbacks marshalled back to MainActor without transferring mutable AV objects. Retain actual pause success before presenting paused state, audio-session ownership through acknowledged stop, stale-result rejection, and serialized command ordering. Immediate MainActor authority invalidation must prevent already queued Speak/Resume from becoming audible. FIFO alone does not guarantee that: a queued start can run before a later invalidation/stop command. Returning early from `stop()` also changes the current synchronous stop boundary. These are substantive privacy/lifecycle changes, not a narrow dispatch edit.

Before proposing that implementation, clarify supported synthesizer ownership with Apple/DTS or a documented sample and design the cancellation boundary. The smallest next native diagnostic, if separately authorized, is the same-runtime stock Play/Pause/Resume/Stop control with explicit command-entry/return thread and monotonic timing markers, compared with the existing serial-owner control. It must retain runtime faults rather than suppress them. It can measure UI-call blocking and command ordering; it cannot alone establish the full app's authority guarantees or zero runtime warnings. Platform escalation should include the reproducible standalone controls, exact runtime/voice, six fault stacks, and exact hosted Pause symbolization.
