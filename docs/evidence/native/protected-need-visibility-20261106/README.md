# S04 protected-need visibility — implementation verification

Foundation 2.1 S04 and D04 require hiding lunch needs to change presentation only. The ingredient detail previously rendered every standalone protected contribution without a visibility control. Existing dinner hiding acts on meal occurrences and does not supply this control for separately protected needs.

The change adds a local Show protected needs toggle when the selected line has protected contributions. Only those detail rows are filtered. Ingredient totals and pack review still read the complete ledger. A visible explanation says hidden needs remain counted. Changing shop or ingredient resets the display preference. English and Spanish catalog entries are included; no persisted demand, permission, entitlement or checkout data model changes.

The new unseeded UI journey imports twelve wraps, reserves two within that amount, hides the lunch detail, checks total twelve and protected amount two, reviews an eight-pack offer requiring two whole packs without stock, restores the detail, and relaunches to check the reservation and total. This is the linked-reservation route; it does not claim the separate named six-taco/four-quesadilla/two-lunch fixture or every locale/device variant.
