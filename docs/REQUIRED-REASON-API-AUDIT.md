# Required-reason API audit

The November 14 review covered the unsigned arm64 archive at `70362b3e`, including the settlement correction. The app and both extensions matched their archived arm64 debug symbols. A scan of the app and both extensions found direct imports for `lstat` and `NSUserDefaults` in the app. Its compiled manifest declares File Timestamp `C617.1` and UserDefaults `CA92.1`. The Share and Widget binaries had no matches in the reviewed imports or Objective-C method names. All four permission prompts in both compiled languages matched the source catalog. The source locations, binary hashes and compiled declarations are in `.build/Release70362b3eNov14/inventory.json` on the release Mac.

Apple lists `lstat` in the File Timestamp category and allows `C617.1` for file metadata inside the app container. `CA92.1` covers app-only defaults. The App Group surfaces exchange files and SQLite data. [Apple's covered API and approved reason list](https://developer.apple.com/documentation/bundleresources/app-privacy-configuration/nsprivacyaccessedapitypes/nsprivacyaccessedapitype)

The app, Share and Widget are separate executable targets. The extensions link the first-party DeviceSurfaces package; it has no covered shipping API hit in this inventory. Both SQLite bridges are system-library targets, not vendored SQLite source or a bundled third-party binary. The generator places the current privacy resource in the app. Apple's [required-reason guidance](https://developer.apple.com/documentation/bundleresources/describing-use-of-required-reason-api) requires each bundle containing an executable or dynamic library that uses a covered API to provide the appropriate manifest. If later extension code adds such access, the extension's own bundle needs review.

The rebuilt unsigned arm64 archive passed the compiled metadata check. Its manifest contains both reasons. The app binary imports `_lstat` and UserDefaults symbols. The direct import scan found no matching imports in Share or Widget. Xcode's generated report shows seven linked data types, three with an Analytics purpose, and no tracking declarations. The report summarizes declared collection and the binary check verifies the packaged API reasons.
